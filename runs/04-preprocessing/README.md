# 04. Предобработка, кодирование варианта и валидация

Три исследования, каждое в отдельной конфигурации из `experiments/`, и основной конфиг с выбранной по их итогам предобработкой: линейные модели получают значения признаков, ограниченные квантилями 0,1 % и 99,9 % обучающей части фолда, и стандартизованные. Все шаги предобработки входят в конвейер модели и обучаются только на обучающей части фолда.

| Конфигурация | Что сравнивается | Моделей |
|---|---|---|
| `config.yaml` | линейные модели с ограничением значений | 29 |
| `experiments/preprocessing.yaml` | способы предобработки на Ridge с `alpha` 0,1, 1, 10 и 100 | 47 |
| `experiments/categorical.yaml` | способы кодирования номера варианта на Ridge | 16 |
| `experiments/validation.yaml` | разбиение без группировки по исходнику | 3 |

Прогон выполнялся в приватном ядре Kaggle на CPU (4 ядра, Python 3.13). Ядро записывает версии библиотек, запускает тесты, затем `main.py` с основным конфигом и с каждой конфигурацией из `experiments/` и в конце пересчитывает признаки для 25 изображений и сравнивает их с таблицей `features/features.csv.gz`. Модели оцениваются кросс-валидацией `StratifiedGroupKFold` на 5 фолдах: стратификация по 10 бинам PSNR, группировка по исходнику, чтобы варианты одного снимка не попадали одновременно в обучение и проверку. Метрика — MAE в дБ на 13 210 изображениях train, у каждого исходника 5 вариантов искажения (`_1` — размытие, `_2` и `_3` — шум, `_5` — сжатие).

## Результат

* 36 тестов пройдены. Прогон занял 5 минут.
* Основной конфиг: лучшая модель — Lasso с `alpha` = 0,0003, MAE 0,800 при разбросе по фолдам 0,013. Без ограничения значений та же модель давала 0,803.
* Сверка признаков: наибольшее относительное расхождение 5·10⁻⁷. Код `src/features.py` воспроизводит таблицу признаков с точностью до её округления до 7 значащих цифр.

Предобработка (для каждого способа — лучшее значение `alpha`):

| Предобработка | Лучший `alpha` | MAE | Разброс по фолдам |
|---|---|---|---|
| Без масштабирования | 0,1 | 0,811 | 0,019 |
| StandardScaler | 1 | 0,807 | 0,017 |
| RobustScaler | 0,1 | 0,808 | 0,017 |
| Квантильное преобразование к нормальному распределению | 1 | 0,830 | 0,007 |
| Ограничение квантилями 1 % и 99 %, StandardScaler | 1 | 0,808 | 0,012 |
| **Ограничение квантилями 0,1 % и 99,9 %, StandardScaler** | 1 | **0,803** | 0,014 |
| Отбор признаков, порог \|ρ\| 0,99 | 1 | 0,812 | 0,015 |
| Отбор признаков, порог \|ρ\| 0,95 | 100 | 0,845 | 0,014 |

## Выводы

* Без масштабирования лучший результат почти такой же, но ошибка быстро растёт с `alpha`, потому что штраф действует на признаки разного масштаба неравномерно. RobustScaler не отличается от StandardScaler.
* Квантильное преобразование ухудшает результат, сильнее всего на шумовом варианте `_3`.
* Ограничение значений квантилями 0,1 % и 99,9 % — лучший способ. В основном конфиге оно уменьшает ошибку всех линейных моделей на 0,001–0,004, не меняется она только у Lasso с `alpha` = 0,3, который почти не отличается от константы. Выигрыш меньше разброса по фолдам, но он получен на `_2`, `_3` и `_4`, а на `_1` и `_5` ошибка почти не меняется. Более сильное ограничение, 1 % и 99 %, выигрыша не даёт.
* Отбор коррелированных признаков и PCA ухудшают результат тем сильнее, чем больше признаков удаляется. Сильно коррелированные признаки отличаются нелинейными деталями, которые важны для модели, а с мультиколлинеарностью справляется регуляризация.
* Номер варианта на вход итоговой модели не подаётся: он известен только из имени файла. Исследование показывает, что one-hot позволяет линейной модели задать свой сдвиг для каждого варианта и снижает ошибку на 0,024, сильнее всего на `_4`. Target encoding заменяет вариант средним PSNR по нему и даёт немного меньший выигрыш. Порядковое кодирование бесполезно: номера вариантов не упорядочены по смыслу.
* Линейная модель не может запомнить отдельный исходник, поэтому без группировки её оценка не улучшается. Разница в пределах разброса по фолдам.
