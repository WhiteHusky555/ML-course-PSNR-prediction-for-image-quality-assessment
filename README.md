# ML-course-PSNR-prediction-for-image-quality-assessment

Курсовой проект по основам машинного обучения на материале соревнования Kaggle [PSNR prediction for image quality assessment](https://www.kaggle.com/competitions/psnr-iqa).

## Задача

Регрессия: по одному искажённому изображению без эталона предсказать его PSNR в децибелах. Метрика соревнования — MAE.

## Данные

Train содержит 13 210 изображений из 2 642 исходников, test — 3 310 изображений из 662 исходников. У каждого исходника 5 вариантов искажения, общих исходников у train и test нет.

Вариант и исходник определяются по имени файла (`<исходник>_<вариант>.png`). Эти сведения используются только для разбиения на фолды и разбивки ошибки и на вход модели не подаются.

## Признаки

Каждое изображение описывается 141 числовым признаком, вычисленным только из его пикселей. Имя файла, размер PNG и другие варианты того же исходника не используются.

| Группа | Число признаков | Что описывает |
|---|---|---|
| `color` | 35 | статистики каналов RGB и яркости, связь между каналами, доля насыщенных пикселей |
| `texture` | 34 | GLCM, гистограмма LBP, отклики фильтров Габора |
| `sharp` | 23 | лапласиан, Tenengrad, Brenner и градиенты на трёх масштабах, устойчивость к повторному размытию |
| `nss` | 16 | статистики нормализованных яркостей (MSCN) в духе модели BRISQUE |
| `comp` | 14 | блочность на нескольких периодах, распределение коэффициентов DCT |
| `noise` | 10 | оценка Immerkaer, остаток после медианного фильтра, разброс в блоках |
| `spectrum` | 9 | доли энергии спектра по частотным кольцам, наклон спектра |

Расчёт для всех 16 520 изображений занимает около 45 минут на 4 ядрах CPU, поэтому готовая таблица хранится в `features/features.csv.gz` и содержит только имена файлов и признаки, округлённые до 7 значащих цифр.

## Разведочный анализ

Анализ данных с графиками и выводами приведён в [eda.ipynb](eda.ipynb). Основные результаты:

* PSNR сильно скошен вправо: медиана 28,06 дБ, 49 % значений лежат в пределах ±0,25 дБ от неё, максимум равен 48,74 дБ. Верхний 1 % значений даёт 9,9 % ошибки константного предсказания.
* Варианты `_1` и `_5` (размытие и сжатие) имеют самый широкий разброс PSNR и хуже всего описываются признаками: внутри этих вариантов наибольшая корреляция Спирмена признака с PSNR равна 0,34 и 0,36. Для шумовых вариантов `_2` и `_3` она равна 0,62 и 0,58.
* Масштабы признаков различаются на шесть порядков, у 822 пар признаков |ρ| > 0,95, первые 18 главных компонент объясняют 95 % дисперсии.
* Распределения признаков в train и test совпадают: в adversarial validation ROC AUC равен 0,502.
* Найдено два повтора одного снимка под разными исходниками, оба между train и test. Внутри train совпадений кадра не найдено.

## Валидация

`StratifiedGroupKFold`, 5 фолдов: стратификация по 10 бинам PSNR, группировка по исходнику. Варианты одного исходника не попадают одновременно в обучение и проверку, что соответствует разделению train и test.

## Результаты

| Модель | MAE, 5 фолдов | Разброс по фолдам | Kaggle public | Kaggle private |
|---|---|---|---|---|
| Lasso, alpha = 0,0003 | 0,800 | 0,013 | — | — |
| ElasticNet, alpha = 0,0001, l1_ratio = 0,9 | 0,801 | 0,014 | — | — |
| Ridge, alpha = 1 | 0,803 | 0,014 | — | — |
| Линейная регрессия | 0,807 | 0,014 | — | — |
| Медиана PSNR | 1,026 | 0,019 | 1,00589 | 0,99441 |

### Линейные модели

Перед линейными моделями значения признаков ограничиваются квантилями 0,1 % и 99,9 % и стандартизуются внутри конвейера, поэтому квантили и параметры масштаба оцениваются только на обучающей части фолда. Выбор этой предобработки описан ниже. Сила регуляризации `alpha` перебиралась по сетке из `config.yaml`: для Ridge от 0,01 до 10 000, для Lasso от 0,0001 до 0,3, для ElasticNet от 0,0001 до 0,1 при `l1_ratio` 0,1, 0,5 и 0,9. Полная таблица из 29 моделей сохраняется в `outputs/results.csv`.

* Все линейные модели с небольшой регуляризацией дают MAE от 0,800 до 0,807. Разница между лучшей из них и обычной линейной регрессией (0,007) меньше разброса по фолдам (0,013–0,014). При 13 210 строках и 141 признаке модель ограничена линейностью связи, а не переобучением.
* С ростом `alpha` ошибка растёт монотонно: Ridge при `alpha` = 10 000 даёт 0,889, Lasso при `alpha` = 0,3 даёт 1,016, почти как медиана. Lasso с лучшим `alpha` = 0,0003 при обучении на всём train оставляет 110 признаков из 141.
* По сравнению с медианой линейные модели снижают ошибку на размытии `_1` (с 1,66 до 1,09) и сжатии `_5` (с 1,94 до 1,17), но на `_4` ошибаются сильнее медианы (1,05 против 0,77). Вероятная причина в том, что линейная модель обучается на квадратичной ошибке и сдвигает прогнозы для узкого пика у 27,9 дБ в сторону редких больших значений.
* Значения `alpha` выбраны по тем же фолдам, на которых измерена ошибка, поэтому оценка лучших строк немного оптимистична.

### Предобработка

Пропусков, бесконечных значений и постоянных признаков в таблице нет (см. `eda.ipynb`), поэтому заполнение и удаление постоянных признаков не требуются. Остальные приёмы сравнивались на Ridge с перебором `alpha` из 0,1, 1, 10 и 100 на тех же фолдах. В таблице для каждого приёма приведено лучшее значение `alpha`. Все шаги входят в конвейер модели и обучаются только на обучающей части фолда. Конфигурация: `experiments/preprocessing.yaml`.

| Предобработка | Лучший alpha | MAE | Разброс по фолдам |
|---|---|---|---|
| Без масштабирования | 0,1 | 0,811 | 0,019 |
| StandardScaler | 1 | 0,807 | 0,017 |
| RobustScaler | 0,1 | 0,808 | 0,017 |
| Квантильное преобразование к нормальному распределению | 1 | 0,830 | 0,007 |
| Ограничение квантилями 1 % и 99 %, StandardScaler | 1 | 0,808 | 0,012 |
| **Ограничение квантилями 0,1 % и 99,9 %, StandardScaler** | 1 | **0,803** | 0,014 |
| Отбор признаков, порог \|ρ\| 0,99 | 1 | 0,812 | 0,015 |
| Отбор признаков, порог \|ρ\| 0,95 | 100 | 0,845 | 0,014 |
| Отбор признаков, порог \|ρ\| 0,9 | 100 | 0,862 | 0,009 |
| PCA, 99 % дисперсии | 100 | 0,853 | 0,012 |
| PCA, 95 % дисперсии | 100 | 0,928 | 0,010 |

* Без масштабирования лучший результат почти такой же, но ошибка быстро растёт с `alpha`: при 100 она равна 0,865 против 0,815 у StandardScaler, потому что штраф действует на признаки разного масштаба неравномерно. RobustScaler не отличается от StandardScaler.
* Квантильное преобразование ухудшает результат за счёт шумовых вариантов: на `_3` ошибка растёт с 0,48 до 0,58.
* Ограничение значений квантилями 0,1 % и 99,9 % обучающей части снижает MAE с 0,807 до 0,803 и разброс по фолдам с 0,017 до 0,014. Более сильное ограничение, 1 % и 99 %, выигрыша не даёт. Выигрыш меньше разброса по фолдам, но он получен на `_2`, `_3` и `_4`, а на `_1` и `_5` ошибка почти не меняется. Поэтому приём включён в основной конфиг для всех линейных моделей.
* Отбор коррелированных признаков и PCA ухудшают результат тем сильнее, чем больше признаков удаляется. Линейная регрессия после отбора по порогу 0,95 даёт 0,851 против 0,810. Сильно коррелированные признаки отличаются нелинейными деталями, которые важны для модели, а с мультиколлинеарностью справляется регуляризация.

### Категориальные признаки

Единственная категориальная величина в данных — номер варианта искажения из имени файла. На вход итоговой модели он не подаётся. Исследование ниже показывает, как разные способы кодирования влияют на линейную модель (Ridge, StandardScaler). Конфигурация: `experiments/categorical.yaml`, результаты сохраняются отдельно и в основной сабмит не попадают.

| Кодирование варианта | Лучший alpha | MAE | MAE на `_4` |
|---|---|---|---|
| Без варианта | 1 | 0,807 | 1,07 |
| One-hot | 10 | 0,783 | 0,99 |
| Target encoding | 10 | 0,790 | 1,02 |
| Ordinal | 1 | 0,806 | 1,07 |

One-hot позволяет линейной модели задать свой сдвиг для каждого варианта и снижает ошибку на 0,024, сильнее всего на `_4`. Target encoding заменяет вариант средним PSNR по нему, рассчитанным с перекрёстным обучением внутри фолда, и даёт немного меньший выигрыш. Порядковое кодирование для линейной модели бесполезно: номера вариантов не упорядочены по смыслу.

### Валидация без группировки

Для сравнения те же модели оценены на `StratifiedKFold` без группировки по исходнику (`experiments/validation.yaml`): MAE Ridge 0,818, линейной регрессии 0,821, медианы 1,026. С группировкой — 0,807, 0,810 и 1,026. Линейная модель не может запомнить отдельный исходник, поэтому варианты одного исходника в обучении и проверке ей не помогают, а разница в пределах разброса по фолдам. Для KNN и деревьев, которые способны находить похожие изображения, сравнение будет повторено.

## Запуск

Проект проверен на Python 3.13, эта же версия используется в ядрах Kaggle. Для загрузки данных нужен токен [Kaggle API](https://www.kaggle.com/docs/api), а правила соревнования должны быть приняты на его странице.

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Загрузка меток:

```bash
pip install kaggle
```

```bash
kaggle competitions download psnr-iqa -f train.csv -p data
```

```bash
kaggle competitions download psnr-iqa -f sample_submission.csv -p data
```

Запуск пайплайна:

```bash
python main.py
```

Таблица результатов сохраняется в `outputs/results.csv`, сабмит лучшей модели — в `outputs/submission.csv`. Состав моделей, их параметры и параметры валидации задаются в `config.yaml`. Список значений в разделе `grid` модели задаёт перебор: каждая комбинация оценивается на тех же фолдах как отдельная модель. Предобработка задаётся параметрами модели: `clip` — квантили для ограничения значений, `select` — порог корреляции Спирмена для отбора признаков, `scaler` — `standard`, `robust` или `quantile`, `pca` — доля объяснённой дисперсии.

Исследования предобработки, кодирования варианта и валидации запускаются отдельными конфигурациями, результаты сохраняются в `outputs/<имя конфигурации>/`:

```bash
python main.py --config experiments/preprocessing.yaml
```

```bash
python main.py --config experiments/categorical.yaml
```

```bash
python main.py --config experiments/validation.yaml
```

Для пересчёта признаков нужны изображения (9,5 ГБ):

```bash
kaggle competitions download psnr-iqa -p data --unzip
```

Затем в `config.yaml` следует указать `features.recompute: true` и снова запустить `main.py`. Таблица `features/features.csv.gz` будет перезаписана.

Ноутбук `eda.ipynb` сохранён с результатами выполнения. Для повторного запуска нужны изображения и Jupyter:

```bash
pip install notebook
```

```bash
jupyter nbconvert --to notebook --execute --inplace eda.ipynb
```

Запуск тестов:

```bash
python -m pytest
```
