# 07. Подбор гиперпараметров бустингов

Подбор параметров LightGBM, XGBoost и CatBoost с помощью Optuna по конфигурации `experiments/tuning.yaml`. Функция потерь у всех трёх моделей — MAE, исходные параметры равны лучшей точке сетки прошлого этапа.

Optuna использует TPE — байесовский метод, который по результатам прошлых испытаний оценивает, какие значения параметров дают малую ошибку, и выбирает следующий набор там, где улучшение вероятнее всего. Перебирались число деревьев (500–4000), шаг обучения (0,005–0,1 для LightGBM и XGBoost, 0,01–0,15 для CatBoost), сложность деревьев (`num_leaves` 15–255, `max_depth` 3–10, `depth` 4–8), минимальный размер листа, доли строк и признаков для каждого дерева и регуляризация. Первым испытанием проверялись исходные параметры, поэтому найденный набор на фолдах поиска не хуже исходного. Поиск для каждой модели ограничен 300 испытаниями и 2 часами.

Каждое испытание — кросс-валидация `StratifiedGroupKFold` на 5 фолдах seed 42: стратификация по 10 бинам PSNR, группировка по исходнику, метрика — MAE в дБ на 13 210 изображениях train. Если оценить подобранную модель на тех же фолдах, её ошибка будет занижена: из многих испытаний выбирается то, которому повезло с конкретным разбиением. Поэтому исходная и подобранная модели сравниваются на фолдах трёх других разбиений (seed 43, 44 и 45), которые в поиске не участвовали. MAE в таблице результатов усреднена по трём разбиениям, `seed_std` — разброс между ними.

Прогон выполнялся в приватном ядре Kaggle на CPU (4 ядра, Python 3.13). Ядро клонирует репозиторий с GitHub и переключается на коммит, указанный в разделе «Код», записывает версии библиотек, запускает тесты и `main.py` с конфигурацией подбора.

## Результат

* 52 теста пройдены. Прогон занял 9 ч 5 мин: поиск — по 2 часа на модель, сравнение на трёх разбиениях — 2 ч 48 мин. Версия Optuna — 5.0.0.
* Число испытаний: LightGBM — 25, XGBoost — 25, CatBoost — 18. Поиск остановлен ограничением по времени: одно испытание занимало в среднем 5–7 минут.

| Модель | Исходные параметры, фолды поиска | Лучшее испытание, фолды поиска |
|---|---|---|
| LightGBM | 0,6489 | 0,6433 |
| XGBoost | 0,6458 | 0,6440 |
| CatBoost | 0,6593 | 0,6569 |

Сравнение на контрольных разбиениях (`results_tuning.csv`):

| Модель | Исходная | Подобранная | Разница | Разница по seed 43, 44, 45 |
|---|---|---|---|---|
| LightGBM | 0,6510 | **0,6446** | −0,0064 | −0,0083, −0,0068, −0,0040 |
| XGBoost | 0,6494 | 0,6482 | −0,0012 | −0,0014, −0,0014, −0,0008 |
| CatBoost | 0,6612 | 0,6600 | −0,0012 | +0,0015, −0,0036, −0,0014 |

Ошибка по вариантам искажения на контрольных разбиениях (`_1` — размытие, `_2` и `_3` — шум, `_5` — сжатие):

## Выводы

* Подбор заметно улучшил только LightGBM: на 0,0064, причём улучшение есть на всех трёх контрольных разбиениях. Подобранный LightGBM — лучшая модель проекта: 0,6446 против 0,6494 у лучшего XGBoost из сетки на тех же разбиениях.
* У XGBoost улучшение одного знака на всех разбиениях, но всего 0,001: параметры из сетки уже были близки к оптимуму в этом пространстве. У CatBoost подобранная модель на одном из разбиений хуже исходной, то есть подбор не дал устойчивого выигрыша.
* Проверка на других разбиениях изменила вывод. На фолдах поиска XGBoost выглядел почти так же хорошо, как LightGBM (0,6440 против 0,6433), а на контрольных разбиениях видно, что у XGBoost улучшение почти нулевое. Разброс между тремя разбиениями (0,0013–0,0018) меньше разницы у LightGBM, поэтому его улучшение не объясняется случайностью разбиения.
* Подобранные параметры LightGBM означают ансамбль из большего числа более крупных деревьев с меньшим шагом и сильной L2-регуляризацией листьев. Выигрыш получен в основном на шумовом варианте `_3` и на `_4`. На размытии `_1` и сжатии `_5` ошибка не изменилась: ограничение на этих вариантах связано с признаками, а не с параметрами модели.
* Ошибка между фолдами на контрольных разбиениях больше (около 0,02), чем на разбиении seed 42 (0,008–0,012): разбиения различаются по сложности. Поэтому модели сравниваются парно на одних и тех же фолдах, а не по абсолютным значениям разных разбиений.
* Поиск не сошёлся. У LightGBM лучшее испытание было последним, а шаг обучения оказался у нижней границы диапазона, число деревьев — близко к верхней. При большем времени и расширенных границах результат, вероятно, можно улучшить.
