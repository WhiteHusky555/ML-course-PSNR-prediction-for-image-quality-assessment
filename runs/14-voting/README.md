# 14. VotingRegressor

Расчёт выполнен локально на CPU 21 ноября 2026 года. Цель — явно проверить пункт Voting из чек-листа и сопоставить его с арифметическим средним прогнозов тех же участников.

## Методика

Три модели: Ridge alpha=1 с ограничением квантилями 0,001/0,999 и StandardScaler; DecisionTreeRegressor max_depth=10, min_samples_leaf=5; HistGradientBoostingRegressor с loss=absolute_error, 200 итерациями, 15 листьями и learning_rate=0,1, без early stopping. Параметры зафиксированы до расчёта, перебора и выбора весов нет. Полная конфигурация — в config.json.

На входе 155 признаков. StratifiedGroupKFold: 5 фолдов, 10 бинов PSNR, seed=42; используется общий make_folds проекта. Участники VotingRegressor заново обучаются внутри каждого фолда, предобработка Ridge — только на обучающей части. Из архивных файлов прогона 11 берутся только имена и метки; сохранённые прогнозы не используются. CNN не переобучаются и в этот ансамбль не входят.

VotingRegressor(weights=None) усредняет прогнозы своих обученных estimators_. Для validation и test каждого фолда отдельно посчитано ручное среднее тех же участников и проверено равенство с допуском 1e-12. Максимальная разница до сохранения CSV — 0. Test-прогноз каждого метода усреднён по пяти фолдам.

Это новый ансамбль из трёх моделей. Его нельзя считать повторным измерением старого среднего семи моделей из прогона 10. Для данного эксперимента базовые модели обучаются внутри проверяемых фолдов; здесь нет дополнительной метамодели на готовых OOF.

## Результат

| Модель | CV MAE | Стандартное отклонение по фолдам |
|---|---:|---:|
| histgb | 0.660950 | 0.012725 |
| voting | 0.687948 | 0.006434 |
| manual_mean | 0.687948 | 0.006434 |
| ridge | 0.779918 | 0.009792 |
| tree | 0.781315 | 0.015704 |

Voting MAE 0,687948 хуже лучшего участника HistGradientBoosting (0,660950) на 0,026998. Равные веса позволяют менее точным Ridge и дереву ухудшить прогноз лучшего участника. Voting и ручное среднее совпали: применение класса VotingRegressor само по себе не улучшает арифметическое среднее.

Основное решение проекта остаётся LightGBM-стекингом с моделями на 155 признаках и двумя CNN. Этот запуск закрывает отдельную проверку Voting; сабмит на Kaggle не отправлялся.

## Воспроизведение и проверка

Из корня репозитория в окружении requirements.txt:

```powershell
python runs/14-voting/reproduce.py
```

По умолчанию новые результаты попадут в outputs/voting. Параметр --output задаёт другую папку. Доступ к сети, исходные изображения и токен Kaggle не нужны: таблица признаков и метки уже в репозитории.

В папке сохранены results.csv, fold_scores.csv, oof_predictions.csv с номерами фолдов, test_predictions.csv, submission_voting.csv и verification.json. Последний содержит версии окружения, SHA-256 входов и конфига, максимальное отклонение Voting от среднего. Для обучения использована кодовая база 39e1fa8 с добавленными файлами этого эксперимента.

Проверены 13210 строк OOF и 3310 test, уникальность имён, конечность значений, отсутствие пересечения групп, покрытие всех пяти фолдов. После записи CSV независимо пересчитаны все MAE, равенство Voting среднему и соответствие submission_voting.csv прогнозам test. Полный набор тестов проекта не перезапускался: код основного пайплайна не менялся.

Документация использованной версии: [VotingRegressor, scikit-learn 1.6](https://scikit-learn.org/1.6/modules/generated/sklearn.ensemble.VotingRegressor.html).
