Курсовой проект по основам машинного обучения на материале соревнования Kaggle [PSNR prediction for image quality assessment](https://www.kaggle.com/competitions/psnr-iqa).

## Задача

Регрессия: по одному искажённому изображению без эталона предсказать его PSNR в децибелах. Метрика соревнования — MAE.

## Данные

Train содержит 13 210 изображений из 2 642 исходников, test — 3 310 изображений из 662 исходников. У каждого исходника 5 вариантов искажения, общих исходников у train и test нет.

Вариант и исходник определяются по имени файла (`<исходник>_<вариант>.png`). Эти сведения используются только для разбиения на фолды и разбивки ошибки и на вход модели не подаются.

## Признаки

Каждое изображение описывается 141 числовым признаком, вычисленным только из его пикселей. Имя файла, размер PNG и другие варианты того же исходника не используются.

| Группа | Число признаков | Что описывает |
|---|---|---|
| `color` | 35 | статистики каналов RGB и яркости, связь между каналами, доля насыщенных пикселей |
| `texture` | 34 | GLCM, гистограмма LBP, отклики фильтров Габора |
| `sharp` | 23 | лапласиан, Tenengrad, Brenner и градиенты на трёх масштабах, устойчивость к повторному размытию |
| `nss` | 16 | статистики нормализованных яркостей (MSCN) в духе модели BRISQUE |
| `comp` | 14 | блочность на нескольких периодах, распределение коэффициентов DCT |
| `noise` | 10 | оценка Immerkaer, остаток после медианного фильтра, разброс в блоках |
| `spectrum` | 9 | доли энергии спектра по частотным кольцам, наклон спектра |

Расчёт для всех 16 520 изображений занимает около 45 минут на 4 ядрах CPU, поэтому готовая таблица хранится в `features/features.csv.gz` и содержит только имена файлов и признаки, округлённые до 7 значащих цифр.

## Разведочный анализ

Анализ данных с графиками и выводами приведён в [eda.ipynb](eda.ipynb). Основные результаты:

* PSNR сильно скошен вправо: медиана 28,06 дБ, 49 % значений лежат в пределах ±0,25 дБ от неё, максимум равен 48,74 дБ. Верхний 1 % значений даёт 9,9 % ошибки константного предсказания.
* Варианты `_1` и `_5` (размытие и сжатие) имеют самый широкий разброс PSNR и хуже всего описываются признаками: внутри этих вариантов наибольшая корреляция Спирмена признака с PSNR равна 0,34 и 0,36. Для шумовых вариантов `_2` и `_3` она равна 0,62 и 0,58.
* Масштабы признаков различаются на шесть порядков, у 822 пар признаков |ρ| > 0,95, первые 18 главных компонент объясняют 95 % дисперсии.
* Распределения признаков в train и test совпадают: в adversarial validation ROC AUC равен 0,502.
* Найдено два повтора одного снимка под разными исходниками, оба между train и test. Внутри train совпадений кадра не найдено.

## Валидация

`StratifiedGroupKFold`, 5 фолдов: стратификация по 10 бинам PSNR, группировка по исходнику. Варианты одного исходника не попадают одновременно в обучение и проверку, что соответствует разделению train и test.

### Линейные модели

Перед линейными моделями значения признаков ограничиваются квантилями 0,1 % и 99,9 % и стандартизуются внутри конвейера, поэтому квантили и параметры масштаба оцениваются только на обучающей части фолда. Выбор этой предобработки описан ниже. Сила регуляризации `alpha` перебиралась по сетке из `config.yaml`: для Ridge от 0,01 до 10 000, для Lasso от 0,0001 до 0,3, для ElasticNet от 0,0001 до 0,1 при `l1_ratio` 0,1, 0,5 и 0,9. Полная таблица всех моделей основного конфига (121 строка) сохраняется в `outputs/results.csv`.

* Все линейные модели с небольшой регуляризацией дают MAE от 0,800 до 0,807. Разница между лучшей из них и обычной линейной регрессией (0,007) меньше разброса по фолдам (0,013–0,014). При 13 210 строках и 141 признаке модель ограничена линейностью связи, а не переобучением.
* С ростом `alpha` ошибка растёт монотонно: Ridge при `alpha` = 10 000 даёт 0,889, Lasso при `alpha` = 0,3 даёт 1,016, почти как медиана. Lasso с лучшим `alpha` = 0,0003 при обучении на всём train оставляет 110 признаков из 141.
* По сравнению с медианой линейные модели снижают ошибку на размытии `_1` (с 1,66 до 1,09) и сжатии `_5` (с 1,94 до 1,17), но на `_4` ошибаются сильнее медианы (1,05 против 0,77). Вероятная причина в том, что линейная модель обучается на квадратичной ошибке и сдвигает прогнозы для узкого пика у 27,9 дБ в сторону редких больших значений.
* Значения `alpha` выбраны по тем же фолдам, на которых измерена ошибка, поэтому оценка лучших строк немного оптимистична.

### Предобработка

Пропусков, бесконечных значений и постоянных признаков в таблице нет (см. `eda.ipynb`), поэтому заполнение и удаление постоянных признаков не требуются. Остальные приёмы сравнивались на Ridge с перебором `alpha` из 0,1, 1, 10 и 100 на тех же фолдах. В таблице для каждого приёма приведено лучшее значение `alpha`. Все шаги входят в конвейер модели и обучаются только на обучающей части фолда. Конфигурация: `experiments/preprocessing.yaml`.

| Предобработка | Лучший alpha | MAE | Разброс по фолдам |
|---|---|---|---|
| Без масштабирования | 0,1 | 0,811 | 0,019 |
| StandardScaler | 1 | 0,807 | 0,017 |
| RobustScaler | 0,1 | 0,808 | 0,017 |
| Квантильное преобразование к нормальному распределению | 1 | 0,830 | 0,007 |
| Ограничение квантилями 1 % и 99 %, StandardScaler | 1 | 0,808 | 0,012 |
| **Ограничение квантилями 0,1 % и 99,9 %, StandardScaler** | 1 | **0,803** | 0,014 |
| Отбор признаков, порог \|ρ\| 0,99 | 1 | 0,812 | 0,015 |
| Отбор признаков, порог \|ρ\| 0,95 | 100 | 0,845 | 0,014 |
| Отбор признаков, порог \|ρ\| 0,9 | 100 | 0,862 | 0,009 |
| PCA, 99 % дисперсии | 100 | 0,853 | 0,012 |
| PCA, 95 % дисперсии | 100 | 0,928 | 0,010 |

* Без масштабирования лучший результат почти такой же, но ошибка быстро растёт с `alpha`: при 100 она равна 0,865 против 0,815 у StandardScaler, потому что штраф действует на признаки разного масштаба неравномерно. RobustScaler не отличается от StandardScaler.
* Квантильное преобразование ухудшает результат за счёт шумовых вариантов: на `_3` ошибка растёт с 0,48 до 0,58.
* Ограничение значений квантилями 0,1 % и 99,9 % обучающей части снижает MAE с 0,807 до 0,803 и разброс по фолдам с 0,017 до 0,014. Более сильное ограничение, 1 % и 99 %, выигрыша не даёт. Выигрыш меньше разброса по фолдам, но он получен на `_2`, `_3` и `_4`, а на `_1` и `_5` ошибка почти не меняется. Поэтому приём включён в основной конфиг для всех линейных моделей.
* Отбор коррелированных признаков и PCA ухудшают результат тем сильнее, чем больше признаков удаляется. Линейная регрессия после отбора по порогу 0,95 даёт 0,851 против 0,810. Сильно коррелированные признаки отличаются нелинейными деталями, которые важны для модели, а с мультиколлинеарностью справляется регуляризация.

### KNN, решающее дерево и случайный лес

Для KNN используется та же предобработка, что и для линейных моделей: без масштабирования расстояние определялось бы признаками с наибольшим масштабом. Деревья не зависят от монотонных преобразований признаков, поэтому получают признаки без изменений. Сетки параметров заданы в `config.yaml`:

| Модель | Параметры | Число моделей |
|---|---|---|
| KNN | `n_neighbors` 3, 5, 10, 20, 50, 100; `weights` uniform и distance; `metric` euclidean и manhattan | 24 |
| Решающее дерево | `max_depth` 3, 5, 10, 20, без ограничения; `min_samples_leaf` 1, 5, 20, 100 | 20 |
| Random Forest | 300 деревьев; `max_features` sqrt, 0,33, 0,5; `min_samples_leaf` 1, 3, 10 | 9 |

В таблицу результатов добавлен столбец `train_mae` — средняя по фолдам ошибка на обучающей части. Разница между ним и MAE на проверке показывает степень переобучения. Для решающего дерева без ограничения размера листа (`min_samples_leaf` = 1):

| max_depth | MAE на обучении | MAE на проверке |
|---|---|---|
| 3 | 0,839 | 0,851 |
| 5 | 0,756 | 0,808 |
| 10 | 0,502 | 0,824 |
| 20 | 0,063 | 0,919 |
| без ограничения | 0,000 | 0,936 |

* Дерево показывает типичную картину переобучения: с ростом глубины ошибка на обучении падает до нуля, а на проверке после глубины 5 растёт. Ограничение листа 100 объектами останавливает рост дерева раньше, чем ограничение глубины: при `max_depth` 10, 20 и без ограничения результат одинаковый, 0,780 при ошибке на обучении 0,725. Одиночное дерево лишь немного лучше линейных моделей.
* У KNN оптимум находится при 10–20 соседях. При 3 соседях модель переобучается (0,792), при 100 слишком сглаживает (0,776). Манхэттенское расстояние лучше евклидова при любом числе соседей на 0,01–0,02: сумма модулей меньше зависит от отдельных признаков с большими отклонениями. Веса по расстоянию дают выигрыш не больше 0,004. При таких весах ошибка на обучении равна нулю, потому что ближайшим соседом объекта оказывается он сам.
* Random Forest — лучшая модель этапа: 0,688 против 0,800 у Lasso при разбросе по фолдам 0,004 вместо 0,013. Ограничение листа 3 объектами лучше, чем 1 (0,697) и 10 (0,691). `max_features` 0,33 и 0,5 дают одинаковый результат, `sqrt` хуже примерно на 0,009. Отдельные деревья леса переобучены (ошибка на обучении 0,32), но усреднение 300 деревьев на случайных подвыборках снижает дисперсию прогноза.
* По сравнению с Lasso лес сильнее всего снижает ошибку на шумовых вариантах (`_2` с 0,21 до 0,10, `_3` с 0,48 до 0,38) и на `_4` (с 1,05 до 0,84). На размытии `_1` и сжатии `_5` выигрыш небольшой (с 1,09 до 1,02 и с 1,17 до 1,12), и на эти два варианта приходится 62 % ошибки леса. На `_4` лес по-прежнему уступает медиане (0,84 против 0,77).

### Градиентный бустинг

Градиентный бустинг строит ансамбль деревьев последовательно. Каждое новое дерево приближает антиградиент функции потерь по текущим прогнозам ансамбля, а его вклад умножается на шаг обучения. Деревья случайного леса независимы, и усреднение снижает дисперсию прогноза. В бустинге каждое дерево исправляет ошибки предыдущих, поэтому снижается смещение. Функция потерь определяет, что именно исправляет следующее дерево. При квадратичной ошибке это остатки, и значения в листьях равны их средним. При MAE антиградиент равен знаку остатка, а значения в листьях равны медианам остатков. Функция Huber квадратична для остатков меньше порога и линейна для больших остатков.

Сравниваются пять реализаций:

* `GradientBoostingRegressor` из scikit-learn — классический алгоритм: перебирает все пороги разбиения и работает в одном потоке.
* `HistGradientBoostingRegressor`, LightGBM и XGBoost с `tree_method: hist` заранее разбивают значения каждого признака на 255–256 интервалов и ищут разбиение по гистограммам, что на порядок быстрее. LightGBM и `HistGradientBoostingRegressor` наращивают дерево по листьям, каждый раз разбивая лист с наибольшим снижением потерь, поэтому сложность дерева задаётся числом листьев. XGBoost наращивает дерево по уровням, сложность задаётся глубиной.
* CatBoost строит симметричные деревья: на одном уровне все узлы используют одно и то же разбиение.

Для каждой реализации перебирались функция потерь и сложность деревьев. Число деревьев и шаг обучения фиксированы, ранняя остановка не используется: при ней число деревьев выбиралось бы по проверочной части фолда.

| Модель | Постоянные параметры | Сетка | Число моделей |
|---|---|---|---|
| GradientBoosting | 1000 деревьев, шаг 0,05, `subsample` 0,8, `max_features` 0,7 | `loss` squared_error, absolute_error, huber; `max_depth` 3, 5 | 6 |
| HistGradientBoosting | 2000 деревьев, шаг 0,02, `max_features` 0,7 | `loss` squared_error, absolute_error; `max_leaf_nodes` 15, 31, 63 | 6 |
| LightGBM | 2000 деревьев, шаг 0,02, `subsample` 0,8, `colsample_bytree` 0,7 | `objective` l2, l1, huber; `num_leaves` 15, 31, 63 | 9 |
| XGBoost | 2000 деревьев, шаг 0,02, `subsample` 0,8, `colsample_bytree` 0,7 | `objective` squarederror, absoluteerror, pseudohubererror; `max_depth` 4, 6, 8 | 9 |
| CatBoost | 2000 деревьев, шаг 0,05 | `loss_function` RMSE, MAE, Huber с порогом 1; `depth` 4, 6, 8 | 9 |

У `HistGradientBoostingRegressor` в scikit-learn 1.6 нет функции потерь Huber. XGBoost и CatBoost с функцией Huber начинают обучение с нулевого прогноза. Градиент Huber ограничен по модулю, поэтому модель не может дойти до значений PSNR около 28 дБ. В пробном запуске на части данных XGBoost расходился, а CatBoost останавливался на ошибке около 1,7. Для этих двух моделей задан параметр `center_target`: перед обучением из PSNR вычитается его среднее по обучающей части фолда, а к прогнозу оно прибавляется обратно.

Лучшая MAE для каждой реализации и функции потерь:

| Модель | Квадратичная ошибка | Huber | MAE |
|---|---|---|---|
| GradientBoosting | 0,698 | 0,675 | 0,663 |
| HistGradientBoosting | 0,685 | — | 0,650 |
| LightGBM | 0,687 | 0,660 | 0,649 |
| XGBoost | 0,676 | 0,666 | **0,646** |
| CatBoost | 0,687 | 0,667 | 0,660 |

|---|---|---|---|---|---|

| Lasso, alpha = 0,0003 | 1,09 | 0,21 | 0,48 | 1,05 | 1,17 |

| XGBoost, квадратичная ошибка, max_depth = 8 | 0,99 | 0,10 | 0,38 | 0,81 | 1,11 |
| XGBoost, MAE, max_depth = 8 | 0,97 | 0,09 | 0,38 | 0,70 | 1,09 |

* Функция потерь важнее выбора реализации. У всех пяти реализаций MAE лучше квадратичной ошибки на 0,027–0,038. С квадратичной ошибкой бустинг оказывается на уровне случайного леса: от 0,676 до 0,698 против 0,688.
* Выигрыш от MAE почти целиком приходится на `_4`: 0,68–0,71 против 0,80–0,86 при квадратичной ошибке. Бустинги с MAE — первые модели, которые на этом варианте лучше медианы (0,70 против 0,77). В `_4` значения PSNR сосредоточены в узком пике около 27,9 дБ. При квадратичной ошибке значения в листьях равны средним и смещаются к редким большим значениям PSNR, а при MAE они равны медианам и остаются у пика. Кроме того, MAE — метрика соревнования, поэтому модель оптимизирует ту же величину, по которой оценивается. На шумовом варианте `_3` квадратичная ошибка немного лучше, но выигрыш на `_4` больше.
* Huber занимает промежуточное положение. Порог около 1 дБ (0,9 в LightGBM) больше большинства остатков, поэтому около пика Huber ведёт себя как квадратичная ошибка и ограничивает только влияние редких больших остатков.
* С MAE более сложные деревья работают лучше. У XGBoost при глубине 4, 6 и 8 ошибка равна 0,657, 0,646 и 0,646, у LightGBM при 15 и 63 листьях — 0,655 и 0,649. Исключение — CatBoost: глубина 8 у него хуже, чем 6 (0,670 против 0,660), потому что симметричное дерево глубины 8 содержит 256 листьев с общими разбиениями на каждом уровне. С квадратичной ошибкой самые сложные деревья почти запоминают обучающую выборку: ошибка на обучении 0,03–0,07. С MAE у тех же деревьев она равна 0,17–0,32. Градиент MAE ограничен по модулю, поэтому отдельный объект с большим остатком не может сильно сдвинуть значение в листе.
* При функции потерь MAE XGBoost, LightGBM и `HistGradientBoostingRegressor` дают от 0,646 до 0,650. Разница меньше разброса по фолдам (0,008–0,012). CatBoost и классический бустинг хуже на 0,010–0,017, но у них другие шаг обучения и число деревьев, так что это сравнение при неподобранных параметрах. Параметры выбраны по тем же фолдам, на которых измерена ошибка, поэтому оценка лучших строк немного оптимистична.
* Размытие `_1` и сжатие `_5` дают 64 % ошибки лучшей модели. Бустинг уменьшает её на этих вариантах лишь немного: с 1,02 до 0,97 и с 1,12 до 1,09 по сравнению с лесом.
* Время перебора на 4 ядрах CPU: классический бустинг — 136 минут при параллельном обучении фолдов, CatBoost — 51 минута, XGBoost — 32, `HistGradientBoostingRegressor` — 14, LightGBM — 11. Гистограммные реализации дают то же или лучшее качество примерно в 10 раз быстрее классической. `GradientBoostingRegressor` работает в одном потоке, поэтому для него задан параметр `fold_jobs: -1`, и пять фолдов обучаются параллельно. Результат при этом не меняется, что проверяется тестом.

### Подбор гиперпараметров бустингов

Сетка выше перебирает только функцию потерь и сложность деревьев. Остальные параметры LightGBM, XGBoost и CatBoost подбираются с помощью Optuna (`experiments/tuning.yaml`). Optuna использует TPE — байесовский метод, который строит вероятностную модель того, какие значения параметров дают малую ошибку, и выбирает следующий набор там, где улучшение вероятнее всего. В отличие от сетки, число испытаний не растёт экспоненциально с числом параметров.

Для каждой модели функция потерь зафиксирована как MAE, а исходные параметры равны лучшей точке сетки. Перебираются число деревьев, шаг обучения, сложность деревьев, минимальный размер листа, доли строк и признаков для каждого дерева и регуляризация весов листьев. Первым испытанием проверяются исходные параметры, поэтому найденный набор на фолдах поиска не хуже исходного. Поиск для каждой модели ограничен 300 испытаниями и 2 часами.

Параметры ищутся на фолдах с seed 42 — тех же, на которых оценены остальные модели. Если оценивать подобранную модель на них же, её ошибка будет занижена: из многих испытаний выбирается то, которому повезло с конкретным разбиением. Поэтому исходная и подобранная модели сравниваются на фолдах трёх других разбиений (seed 43, 44 и 45), которые в поиске не участвовали. MAE усредняется по трём разбиениям, а разброс между ними сохраняется в столбце `seed_std`.

| Модель | Испытаний | Фолды поиска: исходная → лучшая | Контрольные разбиения: исходная | Подобранная | Разница по seed 43, 44, 45 |
|---|---|---|---|---|---|
| LightGBM | 25 | 0,6489 → 0,6433 | 0,6510 | **0,6446** | −0,0083, −0,0068, −0,0040 |
| XGBoost | 25 | 0,6458 → 0,6440 | 0,6494 | 0,6482 | −0,0014, −0,0014, −0,0008 |
| CatBoost | 18 | 0,6593 → 0,6569 | 0,6612 | 0,6600 | +0,0015, −0,0036, −0,0014 |

* Подбор заметно улучшил только LightGBM: на 0,0064, и улучшение есть на всех трёх контрольных разбиениях. Разброс между разбиениями (0,0013–0,0018) меньше этой разницы. Подобранный LightGBM — лучшая модель проекта. Найденные параметры: 3600 деревьев, шаг 0,005, 202 листа, почти все строки и признаки в каждом дереве, L2-регуляризация листьев 5,4 — то есть больше более крупных деревьев с меньшим шагом и сильной регуляризацией.
* У XGBoost улучшение одного знака на всех разбиениях, но всего 0,001: параметры сетки уже были близки к оптимуму. У CatBoost подобранная модель на одном разбиении хуже исходной, устойчивого выигрыша нет.
* Проверка на других разбиениях изменила вывод: на фолдах поиска XGBoost выглядел почти так же хорошо, как LightGBM (0,6440 против 0,6433), а на контрольных разбиениях его улучшение почти нулевое.
* Выигрыш LightGBM получен на шумовом варианте `_3` (0,405 → 0,383) и на `_4` (0,681 → 0,674). На размытии `_1` и сжатии `_5` ошибка не изменилась: ограничение там в признаках, а не в параметрах модели.
* Поиск остановлен ограничением по времени после 18–25 испытаний и не сошёлся: у LightGBM лучшим оказалось последнее испытание, шаг обучения у нижней границы диапазона, число деревьев близко к верхней.

Подробности, история испытаний и лог — в [runs/07-tuning](runs/07-tuning).

### Полносвязная нейросеть (MLP)

Многослойный перцептрон обучается на тех же 141 признаке, что и остальные модели (`experiments/mlp.yaml`, модуль `src/neural.py`). Сеть написана на Keras с бэкендом TensorFlow: для полносвязной сети Keras даёт слои, оптимизаторы и расписания шага обучения готовыми, и описание сети занимает несколько строк. Модель обёрнута в интерфейс scikit-learn, поэтому проходит через тот же конвейер предобработки и те же фолды, что и остальные модели. Признаки ограничиваются квантилями 0,1 % и 99,9 % и стандартизуются, как для линейных моделей: градиентный спуск плохо работает с признаками разного масштаба. Целевая переменная стандартизуется по обучающей части фолда, а прогноз переводится обратно в дБ, поэтому начальные веса подходят к масштабу PSNR около 28 дБ.

Каждый скрытый слой — полносвязный слой, затем необязательная батч-нормализация, функция активации и необязательный dropout. Батч-нормализация нормирует выходы слоя по мини-батчу и ускоряет обучение глубоких сетей; dropout на каждом шаге случайно отключает часть нейронов и уменьшает переобучение. Сеть обучается мини-батчами, обучающая часть перемешивается в каждой эпохе. Цикл обучения написан явно через `tf.GradientTape`: стандартный `model.fit` в Keras 3.13 на каждом шаге выдаёт предупреждение об устаревшем для numpy 2 преобразовании.

Эксперимент идёт по пунктам чек-листа. Сначала сеть усложняется по шагам, затем каждый параметр меняется по отдельности относительно базовой сети `mlp_base`: три скрытых слоя 256, 128 и 64 нейрона, ReLU, батч-нормализация, dropout 0,1, Adam с шагом 0,001 и косинусным расписанием, мини-батч 256, 100 эпох, функция потерь MAE.

| Модель | Что проверяется |
|---|---|
| `mlp_simple` | один скрытый слой из 128 нейронов с ReLU: два полносвязных слоя и активация между ними |
| `mlp_depth` | больше слоёв: 256–128, 256–128–64, 512–256–128–64 |
| `mlp_batchnorm` | 256–128–64 с батч-нормализацией |
| `mlp_dropout` | плюс dropout 0,1, 0,2, 0,3 и 0,5 |
| `mlp_base` | плюс косинусное расписание шага обучения |
| `mlp_width` | размеры слоёв 64–32–16, 512–256–128, 1024–512–256 |
| `mlp_activation` | функции активации GELU, SiLU, tanh, ELU |
| `mlp_optimizer`, `mlp_sgd` | оптимизаторы AdamW, RMSprop и SGD с моментом 0,9 (шаг 0,01 и 0,05) |
| `mlp_learning_rate` | шаг обучения 0,0003, 0,003, 0,01 |
| `mlp_batch_size` | мини-батч 64 и 1024 |
| `mlp_epochs` | 50 и 200 эпох |
| `mlp_loss` | функции потерь MSE и Huber |
| `mlp_combined`, `mlp_combined_sgd` | сочетания лучших значений: активации ELU и SiLU с dropout 0,2 и 0,3, а также ELU с dropout 0,2 и SGD с шагом 0,05 |

### Категориальные признаки

Единственная категориальная величина в данных — номер варианта искажения из имени файла. На вход итоговой модели он не подаётся. Исследование ниже показывает, как разные способы кодирования влияют на линейную модель (Ridge, StandardScaler). Конфигурация: `experiments/categorical.yaml`, результаты сохраняются отдельно и в основной сабмит не попадают.

| Кодирование варианта | Лучший alpha | MAE | MAE на `_4` |
|---|---|---|---|
| Без варианта | 1 | 0,807 | 1,07 |
| One-hot | 10 | 0,783 | 0,99 |
| Target encoding | 10 | 0,790 | 1,02 |
| Ordinal | 1 | 0,806 | 1,07 |

One-hot позволяет линейной модели задать свой сдвиг для каждого варианта и снижает ошибку на 0,024, сильнее всего на `_4`. Target encoding заменяет вариант средним PSNR по нему, рассчитанным с перекрёстным обучением внутри фолда, и даёт немного меньший выигрыш. Порядковое кодирование для линейной модели бесполезно: номера вариантов не упорядочены по смыслу.

### Валидация без группировки

Для сравнения те же модели оценены на `StratifiedKFold` без группировки по исходнику (`experiments/validation.yaml`). Без группировки другие варианты того же снимка оказываются в обучающей части, и модель может использовать их при прогнозе.

| Модель | С группировкой | Без группировки | Разница |
|---|---|---|---|
| Медиана | 1,026 | 1,026 | 0,000 |
| Линейная регрессия | 0,810 | 0,821 | +0,011 |
| Ridge, alpha = 1 | 0,807 | 0,818 | +0,011 |
| Решающее дерево, max_depth = 10, min_samples_leaf = 100 | 0,780 | 0,771 | −0,009 |
| KNN, manhattan, 3 соседа, веса по расстоянию | 0,792 | 0,752 | −0,040 |
| KNN, manhattan, 10 соседей, веса по расстоянию | 0,752 | 0,734 | −0,018 |
| KNN, manhattan, 20 соседей, веса по расстоянию | 0,747 | 0,739 | −0,008 |
| Random Forest, max_features = 0,33, min_samples_leaf = 3 | 0,688 | 0,684 | −0,004 |

* Линейная модель не может запомнить отдельный исходник, поэтому без группировки её оценка не улучшается, а разница в пределах разброса по фолдам.
* Сильнее всего разбиение без группировки завышает качество KNN с малым числом соседей: при 3 соседях ошибка снижается на 0,040, а лучшим становится 10 соседей вместо 20. Среди ближайших соседей оказываются другие варианты того же снимка. Чем больше соседей усредняется, тем меньше их вклад.
* Для дерева и леса разница не превышает разброса по фолдам (0,011–0,015 без группировки). Варианты одного исходника искажены по-разному, поэтому их признаки далеки друг от друга и запомнить снимок по ним трудно.
* В целом утечка через варианты одного исходника невелика, но она меняет выбор параметров KNN. Поэтому для подбора моделей используется разбиение с группировкой, которое соответствует разделению train и test.

## Запуск

Проект проверен на Python 3.13, эта же версия используется в ядрах Kaggle. Для загрузки данных нужен токен [Kaggle API](https://www.kaggle.com/docs/api), а правила соревнования должны быть приняты на его странице.

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Загрузка меток:

```bash
pip install kaggle
```

```bash
kaggle competitions download psnr-iqa -f train.csv -p data
```

```bash
kaggle competitions download psnr-iqa -f sample_submission.csv -p data
```

Запуск пайплайна:

```bash
python main.py
```

Таблица результатов сохраняется в `outputs/results.csv`, сабмит лучшей модели — в `outputs/submission.csv`. Логи и таблицы результатов всех прогонов на Kaggle с пояснениями собраны в [runs/](runs). На 4 ядрах CPU основной конфиг считается около 5,5 часа, из них больше 2 часов занимает `GradientBoostingRegressor` и примерно по часу — Random Forest и CatBoost. Состав моделей, их параметры и параметры валидации задаются в `config.yaml`. Список значений в разделе `grid` модели задаёт перебор: каждая комбинация оценивается на тех же фолдах как отдельная модель. Предобработка задаётся параметрами модели: `clip` — квантили для ограничения значений, `select` — порог корреляции Спирмена для отбора признаков, `scaler` — `standard`, `robust` или `quantile`, `pca` — доля объяснённой дисперсии. Параметр `center_target: true` центрирует целевую переменную по обучающей части, `fold_jobs` задаёт число фолдов, которые обучаются параллельно; он нужен однопоточным моделям.

Исследования предобработки, кодирования варианта, валидации, подбор гиперпараметров и эксперимент с нейросетью запускаются отдельными конфигурациями, результаты сохраняются в `outputs/<имя конфигурации>/`. В конфигурации подбора у модели есть раздел `search` с границами параметров (`low`, `high`, `log`, `step` или список `choices`), а раздел `tuning` задаёт число испытаний, ограничение времени и seed разбиений для сравнения. Кроме таблицы результатов, подбор сохраняет найденные параметры в `best_params.yaml` и историю испытаний каждой модели в `trials_<модель>.csv`.

```bash
python main.py --config experiments/preprocessing.yaml
```

```bash
python main.py --config experiments/categorical.yaml
```

```bash
python main.py --config experiments/validation.yaml
```

```bash
python main.py --config experiments/tuning.yaml
```

```bash
python main.py --config experiments/mlp.yaml
```

Для пересчёта признаков нужны изображения (9,5 ГБ):

```bash
kaggle competitions download psnr-iqa -p data --unzip
```

Затем в `config.yaml` следует указать `features.recompute: true` и снова запустить `main.py`. Таблица `features/features.csv.gz` будет перезаписана.

Ноутбук `eda.ipynb` сохранён с результатами выполнения. Для повторного запуска нужны изображения и Jupyter:

```bash
pip install notebook
```

```bash
jupyter nbconvert --to notebook --execute --inplace eda.ipynb
```

Тесты запускаются в GitHub Actions при каждом push в `main` и в pull request. Локальный запуск:

```bash
python -m pytest
```
