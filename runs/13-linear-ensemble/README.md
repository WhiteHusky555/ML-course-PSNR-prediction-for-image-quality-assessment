# 13. Линейная регрессия и Ridge в стекинге

## Постановка

Проверены LinearRegression и Ridge с alpha = 0,01; 0,1; 1; 10; 100; 1000. Они получают семь прогнозов: LightGBM, XGBoost, CatBoost, MLP SiLU, MLP ELU и две EfficientNetB0 (целые изображения и вырезки). Числа 155 и 167 обозначают набор признаков базовых табличных моделей; на вход линейного стекера поступают именно семь прогнозов, а не 155/167 признаков. CNN получают пиксели.

Использованы сохранённые прогнозы контрольной и экспериментальной частей прогона 12 и CNN прогона 09. Базовые модели не переобучались. В обеих частях один порядок строк, StratifiedGroupKFold с 5 фолдами, 10 бинами PSNR и seed 42. Прогнозы имеют общую шкалу дБ, масштабирование не применялось. LinearRegression и Ridge минимизируют квадратичную ошибку; итоговое сравнение выполняется по MAE. Взвешенное среднее и LightGBM-стекер обучаются с целью минимизации MAE.

Расчёт выполнен локально на CPU Windows, Python 3.13.16, за 53 секунды. Основные библиотеки имеют те же версии, что на Kaggle; точные версии — в `versions.json`. Исходное состояние репозитория: `1289a58`, новые конфигурация и скрипт сохранены в этом этапе. Это локальный прогон, а не новый запуск Kaggle.

Лучший Ridge **в проверенной сетке** — alpha = 1000: MAE 0,505995 на 155 признаках. Он лучше LinearRegression (0,509343), но хуже взвешенного среднего (0,484687) и LightGBM-стекера (0,450888). Лучшее значение находится на границе сетки; глобальный оптимум alpha не установлен. Расширение сетки в этот эксперимент не входило.

Дополнительные 12 комбинаций немного улучшили LinearRegression (0,509343 → 0,508806), но лучший из проверенных Ridge не улучшили (0,505995 → 0,506030). Убедительных оснований переводить основное решение на 167 признаков не появилось. Основной результат проекта остаётся стекингом LightGBM с базовыми моделями на 155 признаках.

## Коэффициенты

`baseline/coefficients.csv` и `combinations/coefficients.csv` содержат коэффициенты и свободный член каждой линейной метамодели для каждого из пяти фолдов; `coefficients_mean.csv` — их средние. Прогноз имеет вид `intercept + sum(coef_i * prediction_i)`. Коэффициенты не являются долями или процентами: могут быть отрицательными и не обязаны давать в сумме 1.

Для 155 признаков средние коэффициенты LinearRegression: LightGBM 0,2609; XGBoost 0,5032; CatBoost −0,4851; MLP SiLU 0,6746; MLP ELU −0,5252; EfficientNet на целых изображениях 0,6177; EfficientNet на вырезках 0,0386. Свободный член −2,3859 дБ. Отрицательные коэффициенты компенсируют сочетания коррелированных прогнозов; они не означают, что модель сама по себе вредна.

При Ridge alpha = 1000 коэффициенты становятся меньше по модулю: соответственно 0,1406; 0,2498; −0,1580; 0,2591; −0,0334; 0,5393; 0,0654, свободный член −1,7722 дБ. Наибольший положительный коэффициент у EfficientNet на целых изображениях. Фиксированная линейная комбинация в этом эксперименте уступает нелинейному стекеру; разница функций потерь также может влиять на сравнение по MAE.

## Проверка и ограничения

Прошли 33 теста существующих моделей и ансамблей. Скрипт проверил полноту и уникальность имён, совпадение меток и наборов изображений между всеми тремя источниками, конечность прогнозов, 13210 строк train и 3310 test. MAE пересчитаны по сохранённым OOF. Для всех семи линейных моделей и пяти фолдов проверено, что коэффициенты воспроизводят OOF и средние test-прогнозы с точностью 1e-9. MAE всех четырёх прежних ансамблей совпали с прогоном 12 без расхождений. SHA-256 входных файлов записаны в `input_hashes.json` каждого варианта.

Это сравнение на готовых OOF, а не полностью вложенная кросс-валидация. Метамодель не обучается на метках своего проверочного фолда напрямую, но OOF обучающей части получены базовыми моделями, которые могли видеть метки этого проверочного фолда. Поэтому такую оценку нельзя объявлять полностью независимой оценкой всей двухуровневой системы. Для строгой проверки нужны внешние фолды с повторным обучением базовых моделей, включая CNN, внутри каждого внешнего разбиения. Выбор alpha по этим же фолдам добавляет оптимизм оценки лучшей строки. Здесь сохранена общая методика прежних прогонов для сопоставимости.

## Воспроизведение

Из корня репозитория с установленными `requirements.txt`:

```powershell
python runs/13-linear-ensemble/reproduce.py
```

Скрипт использует `experiments/ensemble_linear.yaml`, восстанавливает таблицы имён и меток из сохранённых прогнозов и записывает новые результаты в `outputs/ensemble_linear/`. Интернет, изображения и Kaggle API для этого не нужны. Аргумент `--output` позволяет сохранить результат в другую папку. Настройки обучения основного проекта не меняются.

В `baseline/` и `combinations/` лежат результаты, коэффициенты, оценки по фолдам, OOF и test-прогнозы, а также CSV сабмита лучшего ансамбля. `comparison.csv` содержит все 22 строки сравнения, `run.log` — журнал выполнения.
